# Milestone B: live verification and release hold

Verified 15 November 2026 against `https://nasa-field-shift-production.up.railway.app`. No production feature enablement or deployment was performed. Production release remains blocked by real browser microphone end-to-end testing and unverified distributed rate-limit/abuse controls.

## Actual service contract

| Endpoint | Observed result |
| --- | --- |
| GET `/health` | 200, `status: ok`, `meta_loaded: true` |
| GET `/docs` | 200, Swagger UI |
| GET `/openapi.json` | 200, OpenAPI 3.1, service version 0.1.0 |
| POST `/extract/text` | 200 for partial, unclear, complete, correction and advice-error cases |
| POST `/extract/voice` | 200 for a 349,252-byte WAV synthetic speech test; transcript matched its spoken test sentence |

No route prefix is required. The published schema declares no security schemes or endpoint authentication; tested calls succeeded without credentials. This does not establish an abuse-control policy. Audio multipart fields are `audio`, optional `state`, `lga`, and stringified JSON `context`. The schema does not enumerate accepted audio MIME types or a maximum audio size. WAV was verified; WebM/Opus, MP4/M4A, Ogg and MP3 acceptance remain unverified live. Upstream 25 MB remains a guide statement rather than a measured deployed limit. Frontend remains capped at 3.5 MB.

Observed schema differences resolved:

- Text `message` is 1–3,000 characters, not the provisional frontend 8,000. Client, proxy and textarea now share the 3,000-character constant. A direct 3,001-character request returned 422.
- Actual report `weather_years` contains four-digit strings, e.g. `["2001", "2025"]`. Types and strict validation accept valid four-digit strings or integer years. No conversion or report rewriting occurs.
- Actual `land.facts.ph_crops` omits unrepresented category keys. Those keys are optional in types and validation; absent values are preserved, not filled with invented arrays or scientific claims.
- `advice_page` is an open object in OpenAPI. Full runtime checks still gate entry into the shared results UI; incompatible reports retain the safe text fallback.

1. Text described previous maize and soil/input priorities without a location. Result: partial, missing state/LGA, service-authored clarification (7.6 seconds).
2. Follow-up supplied Kajuru, Kaduna and field details with the **entire preceding response** as context. Result: complete, real advice ID `5a6669a81333dd2e` (7.3 seconds).
3. Follow-up corrected maize to sorghum using the entire second response. Result: complete, seasons `[["sorghum"]]`, soil/input priorities, new advice ID `bafd62596a8b4616` (7.9 seconds).
4. Windows speech synthesis generated a short WAV test sentence about maize and soil. Multipart upload returned 200, an accurate transcript, partial extraction and a state/LGA clarification (5.9 seconds). This is **real audio API testing with synthetic speech**, not a human microphone recording, MediaRecorder test or mobile-device test.
5. Text follow-up to the audio response supplied Kajuru/Kaduna and field details. Result: complete advice, maize history retained (3.0 seconds).
6. `Hello` returned unclear and a service-authored question (2.2 seconds).
7. Unsupported octet-stream `.txt` upload returned 415. Overlong text returned 422.
8. A correction to Apapa, Lagos returned complete extraction with `advice_error` explaining unavailable environmental data, `advice_page: null`, and no missing extraction fields. The frontend's existing advice-error gate preserves context and prevents a success screen.

Normal observed extraction/advice calls completed within the existing 55-second proxy/65-second client deadlines. Actual upstream timeout limits, 429/500/502 induction, network interruption and oversized upstream uploads were not exercised. No load or abuse tests were performed. Those error paths remain covered by isolated automated tests rather than claimed live failures.

## Proxy and security review

Existing proxy restricts action paths, requires matching Origin on POST, validates fields/body/audio/context, uses configured HTTPS, prevents redirects, bounds response size, forwards no incoming credentials/cookies/arbitrary headers, uses no-store, sanitizes error responses and never automatically retries POST. No raw audio/private conversations are logged by application code. Same-origin proxy avoids browser-to-Railway CORS requirements. Existing agricultural browser requests retain their existing CORS architecture.

Origin validation is **not** authentication or protection from a non-browser attacker. No distributed limiter is implemented in this repository or declared by Railway OpenAPI. Backend/platform rate limiting, concurrent-work caps and cost protection must be confirmed/configured before public enablement. An in-memory per-process counter would not provide reliable distributed Vercel protection and was not added as a false substitute.

An attempt to start an enabled localhost verification server was rejected by automatic approval review with `blocked by policy`; the tool supplied no more specific reason. No workaround was used to enable it. The browser microphone journey and enabled local-proxy-to-Railway end-to-end checks remain pending. The production environment, Vercel settings and release flag were not changed.
